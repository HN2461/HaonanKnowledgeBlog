# 全栈部署入门目录：Vue + Express + MongoDB 从本地到公网

资料核对时间：2026-06-08。

这套文档是给刚学完下面这些内容的人准备的：

- 会写 Vue 页面，但还没有真正部署过前端项目。
- 会写 Express 接口，但只在本机 `localhost` 跑过。
- 会连 MongoDB，但还没有处理过生产环境认证、备份和网络暴露。
- 听别人说过 SSH、Nginx、宝塔、PM2、HTTPS，但不知道它们到底谁管什么。

先把一句话放在前面：

> 部署不是“把项目上传到服务器”这么简单。真正部署是让用户能通过域名稳定、安全地访问你的前端页面和后端接口。

## 最终你要搭起来的样子

典型的 Vue + Express + MongoDB 项目上线后，大概是这个链路：

```txt
用户浏览器
  |
  | 访问 https://你的域名.com
  v
Nginx
  |
  |-- 直接返回 Vue 打包后的 dist 静态文件
  |
  |-- 把 /api 请求转发给本机 Express 服务
          |
          v
       Node.js / Express
          |
          v
       MongoDB
```

这里每一层都有自己的职责：

| 层级 | 负责什么 | 小白理解 |
|---|---|---|
| 域名和 DNS | 把域名指向服务器 IP | 用户记域名，不记一串 IP |
| SSH | 远程登录服务器 | 像打开一台远程 Linux 电脑的命令行 |
| Linux | 项目真正运行的系统 | 服务器大多不是 Windows 桌面 |
| Nginx | 静态资源、反向代理、HTTPS 入口 | 用户先碰到 Nginx，再转到你的项目 |
| PM2 或 systemd | 守护 Node 进程 | Express 崩了能重启，服务器重启后能恢复 |
| MongoDB | 存数据库 | 生产环境要认证、限流量入口、备份 |
| 宝塔 | 图形化面板 | 能提速，但不能代替底层理解 |

## 必学、建议学、后续学

### 必学

这些是“没有就很难独立部署”的基础：

- SSH 登录服务器。
- Linux 目录、权限、进程、日志、端口。
- Nginx 静态站点和反向代理。
- Node.js 生产环境运行方式，至少学会 PM2 或 systemd 其中一个。
- `.env` 环境变量。
- 域名、DNS、HTTPS 的基本流程。
- 防火墙或云厂商安全组。
- MongoDB 认证、最小权限、备份、不要公网裸连。

### 建议学

这些能让部署更顺：

- 宝塔面板。
- `scp`、`rsync`、Git 拉代码部署。
- 服务器日志排查。
- 502、404、CORS、数据库连不上等常见错误定位。

### 后续再学

这些很有用，但建议在你手动部署成功一次之后再学：

- Docker。
- Docker Compose。
- GitHub Actions / CI/CD。
- 蓝绿发布、灰度发布、自动回滚。
- Kubernetes。

原因很简单：如果你连 Nginx、端口、日志和环境变量都没搞清楚，一上来学 Docker，会把“容器问题”和“应用本身问题”混在一起。

## 学完后的最低验收标准

学完这套资料，不要求你背命令，但至少要能做到：

- 能用 SSH 登录服务器。
- 能知道项目放在哪个目录。
- 能看懂 Nginx 的 `server`、`location`、`root`、`try_files`、`proxy_pass`。
- 能把 Vue 项目打包成 `dist` 并由 Nginx 访问。
- 能让 Express 在后台常驻运行。
- 能知道 502 多半先看 Nginx 反向代理和 Node 进程。
- 能知道刷新 Vue 子路由 404 要看 `try_files` 或 hash history。
- 能给 MongoDB 开认证，不把 27017 暴露给公网。
- 能用宝塔部署，但也能知道宝塔背后在改 Nginx、PM2、防火墙和证书。
