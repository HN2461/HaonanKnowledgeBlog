> 2026-05-24 复核说明：这一组文章已按当前能核对到的官方资料和本地 Codex 实装情况重新收口。现在仍然不把所有工具写成“完全同一套机制”，但也不再把 Cursor / Claude 简化成“只有 rules 或 commands”。更稳妥的划分是：
>
> 1. `SKILL.md` 这一类可移植的“技能包”思路
> 2. Kiro / Codex / Cursor / Claude Code 当前官方可确认支持的 skills 方案
> 3. `Rules`、`AGENTS.md`、`CLAUDE.md`、自定义命令这类长期规范或快捷入口机制

## 适合先读哪篇

如果主人想先搞清楚“这到底是不是同一套东西”，先看第一篇。

如果主人已经会写 `SKILL.md`，想分清哪些写法还稳、哪些说法已经容易过时，直接看第二篇。

如果主人想拿现成模板开干，看第三篇。

如果主人本身就是前端开发，想直接看“哪些 skills 最该先配、哪些更适合自己做”，再接着看第三篇目录下的补充清单。

如果主人想做团队共享、统一分发、找靠谱来源，看第四篇。

## 本组文章现在的写法原则

- `name`、`description` 仍然是跨工具最稳的基础字段。
- `metadata`、`license`、`compatibility` 这类字段应和 Agent Skills 规范层一起理解，但不要默认每个产品都同等使用它们。
- Cursor 现在应理解为 **Rules / AGENTS.md 与 Skills 并存**，而不是“只有 rules 没有 skills”。
- Claude Code 现在应理解为 **Skills 为总框架，commands 是其中一种快捷入口**，而不是“只有 commands 没有 skills”。

## 建议搭配阅读

- 想给 Codex 本地装技能：先看第四篇，再对照 `~/.codex/skills/` 实际目录。
- 想给项目沉淀长期规范：不要急着把一切都塞进 skill，先判断是不是更适合写 `AGENTS.md`、`CLAUDE.md` 或 `.cursor/rules`。
- 想跨工具复用：先按第一篇的“最小可移植层”写，再看第三篇如何分叉成工具专属 skills、rules 或 command 入口。
- 想专门给前端开发配一套常用 skill：先看第三篇，再看 [补充篇：前端开发常用 Skills 清单与选型建议（2026-05复核）](03_场景模板与案例库/补充篇_前端开发常用Skills清单与选型建议_2026-05.md)。
