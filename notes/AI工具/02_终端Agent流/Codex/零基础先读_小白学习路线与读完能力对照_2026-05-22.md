# 零基础先读：Codex 程序员学习路线与读完能力对照

> 更新时间：2026-05-31  
> 适合谁：第一次系统学 Codex，或者已经看过几篇但仍然觉得“内容很多、真正开发时不知道先用哪篇”的主人。  
> 目标：不是让你背完整套配置字段，而是先能用 Codex 完成第一轮真实开发，再逐步补配置、三端联动和排障能力。  
> 使用方法：先按本文顺序读主线；字段字典、界面对照 SOP、第三方线路和历史排障按需查。

## 1. 先讲清一个现实：你不需要先背完 Codex 所有功能

小白最容易犯的错，不是学得太慢，而是顺序反了：

1. 一上来就背 `model`、`model_provider`、`approval_policy`、`sandbox_mode`
2. 还没进真实仓库，就开始研究 App、IDE、MCP、Worktrees、Automations
3. 看到一堆英文菜单和插件状态词，却不知道下一步该怎么判断

所以这套资料现在按“先能用、再会查、最后会排错”来学。

一句话路线：

1. 先把 CLI 第一日开发跑顺
2. 再看懂英文终端界面
3. 再补配置心智模型
4. 再把 CLI、VS Code 插件和桌面 App 串成日常开发流
5. 真遇到线路、字段、PowerShell、CC Switch 问题时再查附录

## 3. 每篇读完以后，你应该真正会什么

### 3.1 看完第一篇，你应该会

1. 确认当前运行的是哪一份 `codex`
2. 在真实仓库里启动 Codex
3. 用“先读、再定位、再小改、再验证”的节奏完成第一轮任务
4. 分清 CLI、VS Code 插件、脚手架和桌面 App 大致怎么分工

### 3.2 看完第十三篇，你应该会

1. 看懂 CLI 首页、模型选择、推理强度、权限菜单和 slash 菜单
2. 知道 `/status`、`/mcp`、`/plugins`、`/skills` 应该分别看什么
3. 看到红色错误时先按 `path / permission / auth / provider / mcp / node` 分类
4. 会话中断后，先看 diff 和状态，而不是直接继续大改

### 3.3 看完第三篇，你应该会

1. 解释清楚认证、审批、沙箱、配置层级各管什么
2. 说出 `~/.codex/config.toml`、项目 `.codex/config.toml`、`AGENTS.md` 分别管什么
3. 不再把“改了没生效”统统归因成玄学问题

### 3.4 看完第八篇，你应该会

1. 知道 `codex`、`codex exec`、`resume`、`--profile`、`/status`、`/review` 各自干嘛
2. 知道 `config.toml`、`auth.json`、`AGENTS.md`、`.rules` 的职责边界
3. 遇到一个命令或字段名时，能快速查到它属于哪一层

### 3.5 看完第六篇，你应该会

1. 解释清楚 CLI、IDE 扩展、桌面 App 为什么既共享能力、又不完全等价
2. 知道为什么会出现“CLI 能用，插件/App 不行”
3. 知道 Windows-native、WSL agent、`CODEX_HOME` 不一致会带来什么问题

### 3.6 看完第十二篇，你应该会

1. 说出今天最常用的功能点分别在哪个入口用
2. 分清哪些旧说法该删，哪些旧能力该保留
3. 开始按“模型 -> 权限 -> IDE / App / CLI -> Worktrees / Cloud / Review / Automations”这条线做开发

### 3.7 看完第五篇，你应该会

1. 自己写一份最小可用 `config.toml`
2. 知道 `model`、`model_provider`、`approval_policy`、`sandbox_mode` 这些关键字段怎么填
3. 知道“官方默认示例”和“第三方网关当前可用值”之间的区别

### 3.8 看完第七篇，你应该会

1. 按界面对照去找配置和能力入口
2. 把抽象名词和真实界面一一对应
3. 给自己或团队做一套可复现的核对 SOP

## 4. 学完以后，你就应该掌握的 4 个层次

### 4.1 第一层：能跑起来

你应该会：

1. 安装 Codex CLI
2. 看懂版本、登录状态、当前模型
3. 用安全默认权限开一个可用会话

### 4.2 第二层：能稳定使用

你应该会：

1. 用 `/status` 和 `/permissions` 判断当前状态
2. 区分只读、工作区写权限和高权限模式
3. 用 `AGENTS.md` 固定项目规则

### 4.3 第三层：能把它真正用进开发

你应该会：

1. 在 CLI 里读仓库、排错、看 diff
2. 在 IDE 插件里贴着代码做具体改动
3. 在 App 里用 `Worktrees`、`Review pane`、`Built-in Git`、`Integrated terminal`
4. 大任务上用 `Cloud delegation` / `Handoff`

### 4.4 第四层：能自己排错

你应该会：

1. 看 `/status` 和配置覆盖链
2. 查 `model_provider`、`base_url`、`auth.json` / keyring
3. 排查 Windows-native / WSL / `CODEX_HOME` 差异
4. 知道故障该回哪篇专题，而不是乱删配置

## 5. 什么时候该看哪篇，不要乱跳

如果你现在遇到这些情况，直接按下面跳：

1. “我第一次用 Codex，不知道怎么开第一轮任务”：去第一篇
2. “我看不懂 CLI 英文界面和菜单”：去第十三篇
3. “我完全不懂 Codex 配置层次”：去第三篇
4. “我不懂命令名和字段名”：去第八篇
5. “CLI、VS Code 插件、桌面 App 表现不一致”：去第六篇
6. “我想知道现在最常用功能怎么用”：去第十二篇
7. “我知道概念，但不会填配置”：去第五篇
8. “我想确认这些能力在界面上到底在哪”：去第七篇
9. “Codex 在 Windows / Node / PowerShell 上出怪问题了”：去第十篇和 CC Switch 排障专题

---

## 6. 哪些内容不是一开始就深挖的

下面这些内容不是不重要，而是不要在第一个小时就陷进去：

1. 第四篇多线路接入与迁移总手册
2. 第九篇 `.codex` 本地目录深挖
3. 第十篇 PowerShell / MCP / CC Switch 故障复盘
4. 已并入主文的历史入口页（第二篇、第十一篇、rpcod 补充篇）

它们更适合：

1. 你已经会基本使用后，再按需查
2. 你真遇到对应线路、对应环境或对应故障时再看

## 7. 一句话学习地图

如果要把整套资料压缩成一句话，就是：

1. 第一篇让你“能开工”
2. 第十三篇让你“看懂终端”
3. 第三篇让你“懂配置原理”
4. 第八篇让你“会查命令和字段”
5. 第六篇让你“懂 CLI / 插件 / App 分工”
6. 第十二篇让你“会用当前常用功能”
7. 第五篇让你“会填配置”
8. 第七篇让你“能对照界面操作”

## 8. 小白读完后的最低达标标准

如果主人希望这套文档真的做到“小白读完也能掌握 Codex”，最低标准应该是：

1. 能自己跑通一轮真实仓库开发任务
2. 能看懂 CLI 英文菜单和常见错误提示
3. 能分清 CLI / IDE / App 分别适合什么
4. 能说清 `Worktrees`、`Cloud delegation`、`Review pane`、`AGENTS.md`、`MCP` 分别是什么
5. 出问题时知道先去哪个专题排，而不是乱改配置

如果这 5 条做到了，这套文档就不是“堆资料”，而是真的能教会人。
