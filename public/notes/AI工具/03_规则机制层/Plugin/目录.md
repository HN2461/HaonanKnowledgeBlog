Plugin 是 AI 编程工具扩展体系中的"第四极"——如果说 Rules 是"员工手册"、MCP 是"工具箱"、Skill 是"操作菜谱"，那 Plugin 就是"技能套装包"，能把 Skills、MCP 服务器配置、Hooks、Commands、Agents 等多种能力统一打包、一键安装、团队/社区分发。

本系列共 4 篇，覆盖从概念理解到各工具实战再到选型落地的完整路径。

## 覆盖主题

**Plugin 概念与原理**
- Plugin 的定义、核心解决的问题（功能分散 → 统一打包 → 一键分发）
- Plugin vs Skill：私人定制 vs 团队复用的本质区别
- Plugin vs MCP：工具连接 vs 功能打包的定位差异
- Plugin vs Rules：静态规则 vs 动态能力包的互补关系
- 各工具 Plugin 支持现状速览

**Codex Plugin 体系**
- 2026-03-27 OpenAI 正式推出 Codex Plugin 服务
- `.codex-plugin/plugin.json` 清单格式与必填字段
- Marketplace 三级结构：官方仓库 / 项目级 / 用户级
- 本机 `~/.codex/plugins/cache/` 实装分析（documents / presentations / spreadsheets）
- `/plugins` 命令族：浏览、搜索、安装、卸载
- Codex Plugin 当前局限：社区 Marketplace 尚未开放、远程安装受限

**Claude Code Plugin 体系**
- Claude Code 七大扩展组件：CLAUDE.md / Memory / Hooks / Skill / Plugin / MCP / Agent
- Plugin 作为"最高级扩展机制"的定位
- 一个 Plugin 可包含：Slash Commands / Subagents / MCP Servers / Hooks / LSP 配置
- `/plugin install` / `/plugin list` / `/plugin status` 命令
- Marketplace 与社区生态（anthropics/claude-code-plugins）

**选型指南与团队落地**
- 四大扩展机制对比矩阵（定位 / 包含内容 / 分享范围 / 安装方式）
- 选型决策树：什么场景用什么机制
- Cursor / Windsurf / Kiro 当前无独立 Plugin 体系时的替代方案
- 团队协作策略：Plugin 发布 → Marketplace 分享 → 统一配置管理
- 常见误区与避坑指南
