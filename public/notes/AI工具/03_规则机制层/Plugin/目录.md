Plugin 可以理解为 AI 编程工具里的"能力打包层"。如果说 Rules 是"员工手册"，MCP 是"外部工具连接"，Skill 是"任务菜谱"，那 Plugin 更像"可安装的工具包"：把多个能力组织成一个可分发、可复用、可升级的单元。

本系列共 4 篇，覆盖从概念理解到各工具实战，再到团队落地与选型判断的完整路径。

## 覆盖主题

**Plugin 概念与原理**
- Plugin 到底解决什么问题：不是"多一个功能"，而是"把已有能力打包并分发"
- Plugin vs Skill：单流程模板 vs 可安装能力包
- Plugin vs MCP：外部工具连接 vs 打包与分发机制
- Plugin vs Rules：持续生效的规则 vs 按工具原生流程安装的能力包
- 主流 AI 编程工具对独立 Plugin 体系的支持现状

**Codex Plugin 体系**
- OpenAI 官方对 Codex Plugins 与 Skills 的区分
- `.codex-plugin/plugin.json` 与可选伴随结构
- `openai/plugins` 官方示例仓库与本机 `~/.codex/plugins/cache/` 实装目录
- `codex plugin marketplace add|upgrade|remove` CLI 能力
- `~/.codex/config.toml` 中 `marketplaces.*` 与 `plugins.*` 的实际落点

**Claude Code Plugin 体系**
- `/plugin` 命令族与 `claude plugin` CLI 的关系
- 官方 marketplace：`claude-plugins-official`
- 社区 marketplace：`anthropics/claude-plugins-community`
- demo marketplace：`anthropics/claude-code`
- user / project / local / managed 四种 scope
- `.claude-plugin/plugin.json` 为可选文件，`name` 是唯一必填字段

**选型指南与团队落地**
- Rules、MCP、Skill、Plugin 四种机制分别解决什么问题
- 什么时候只写 Skill，什么时候需要升级成 Plugin
- Codex 与 Claude Code 各自适合怎样的插件分发方式
- Cursor / Windsurf / Kiro 没有独立 Plugin 体系时如何替代
