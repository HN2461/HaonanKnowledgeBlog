## 先给总路线

如果主人是程序员，我建议你把 Claude Code 的学习顺序理解成 4 个阶段：

1. 跑通本体：安装、更新、登录、终端工作流
2. 稳定主线：`CLAUDE.md`、权限模式、上下文、验证习惯
3. 加能力层：skills、MCP、plugin、浏览器与文档能力
4. 再折腾扩展：第三方模型线路、IDE 集成、长期自动化

很多旧教程的问题，不是内容完全错，而是把第 3、4 阶段的东西抢在了第 1、2 阶段前面。  
结果就是你知道了很多名词，但真正开工时还是发虚。

## 现在这组文章各自解决什么问题

### 第一篇：先把本体装对、用对

重点解决：

- Claude Code 到底怎么安装、怎么更新
- 为什么不能脚本、brew、winget、npm 混着装
- 终端里常见英文提示是什么意思
- 第一轮最该怎样进入真实项目开工

### 第二篇：把脑子里的层次排整齐

重点解决：

- `CLAUDE.md`、rules、`CLAUDE.local.md` 到底怎么分工
- memory、skills、hooks、MCP、plugin 各自处在哪一层
- 为什么“装了很多东西但不会用”本质上常常是层次没分清

### 第三篇：把“会聊”变成“会推进任务”

重点解决：

- 看陌生仓库怎么问
- 修 bug 怎么问
- 重构怎么问
- 怎样形成 Explore / Plan / Implement / Verify 的节奏

### 第四篇：把配置真正配顺

重点解决：

- settings 作用域怎么分层
- `CLAUDE.md` 怎么写才真有用
- 模式、模型、`effort`、上下文怎么各归其位
- 哪些设置最影响你扩展能力的体验

### 第五篇：中转、Gateway 与多模型线路到底怎么接

重点解决：

- `Base URL`、`Key`、模型映射各自负责什么
- 为什么很多时候不只是“换个 Key”那么简单
- Anthropic 兼容中转、包月线路、Gateway 应该怎么理解
- 最小验证和排障顺序该怎样从薄到厚

### 第六篇：装了很多 Skill、MCP、Plugin，却看不懂终端界面怎么办

重点解决：

- `/mcp`、`/skills`、`/plugin` 各页面里的英文是什么意思
- 哪些是内置命令，哪些是 plugin skill 或 MCP prompt
- `connected`、`failed`、`locked by plugin`、`~40 tok` 这类提示该怎么理解
- “装了但一脸懵”时该怎么从来源、状态和入口三层快速排障

---

## 主人最该优先建立的 5 个观念

1. Claude Code 首先是终端工作流工具，不是聊天窗口换皮
2. 规则层、权限层、记忆层、扩展层必须分开理解
3. 装了扩展不等于一定会自动用，发现和触发是两个阶段
4. 好的 `CLAUDE.md` 比堆更多临时 prompt 更值钱
5. 第三方线路和 IDE 集成应该放在主线稳定之后

## 如果主人今天只想解决一个问题，怎么选

如果你现在最痛的是“我根本不知道怎么开始”，先读第一篇。  
如果你最痛的是“装了一堆 skill / MCP / plugin 还是看不懂终端提示、不会调”，先读第六篇。  
如果你最痛的是“Claude 有时很强有时很飘，不知道为什么”，先读第二篇和第四篇。
