## 1. 先讲清一个现实：你不需要一口气背完 Codex 所有功能

小白最容易犯的错，不是“学得太慢”，而是：

1. 一上来就想把模型、配置、App、IDE、MCP、Worktrees、Automations 全背下来
2. 看到一堆功能名，却不知道先学哪个，结果每篇都懂一点点
3. 最后真正开发时，还是不知道应该先开 CLI、先开 IDE，还是先去改 `config.toml`

所以这套资料现在按“从能用到会用，再到会排错”来学更稳。

你先记一句话就够：

1. 先学“Codex 是怎么工作的”
2. 再学“Codex 现在最常用的功能怎么用”
3. 最后学“出了问题怎么排”

## 3. 每篇读完以后，你应该真正会什么

这部分最重要。  
你不要只问“我看完了没”，要问“我看完之后会不会做这件事”。

### 3.1 看完第三篇，你应该会

1. 解释清楚什么是认证、什么是审批、什么是沙箱、什么是配置层级
2. 说出 `~/.codex/config.toml`、项目 `.codex/config.toml`、`AGENTS.md` 分别管什么
3. 不再把“改了没生效”统统归因成玄学问题

### 3.2 看完第八篇，你应该会

1. 知道 `codex`、`codex exec`、`resume`、`--profile`、`/status`、`/review` 各自干嘛
2. 知道 `config.toml`、`auth.json`、`AGENTS.md`、`.rules` 的职责边界
3. 遇到一个命令或字段名时，能快速查到它属于哪一层

### 3.3 看完第五篇，你应该会

1. 自己写一份最小可用 `config.toml`
2. 知道 `model`、`model_provider`、`approval_policy`、`sandbox_mode` 这些关键字段怎么填
3. 知道“默认示例”和“第三方网关当前可用值”之间的区别

### 3.4 看完第六篇，你应该会

1. 解释清楚 CLI、IDE 扩展、桌面 App 为什么既共享能力、又不完全等价
2. 知道为什么会出现“CLI 能用，插件/App 不行”
3. 知道 Windows-native、WSL agent、`CODEX_HOME` 不一致会带来什么问题

### 3.5 看完第十二篇，你应该会

1. 说出今天最常用的功能点分别在哪个入口用
2. 分清哪些旧说法该删，哪些旧能力该保留
3. 真正开始按“模型 -> 权限 -> IDE / App / CLI -> Worktrees / Cloud / Review / Automations”这条线做开发

### 3.6 看完第七篇，你应该会

1. 按截图定位去找配置和能力入口
2. 把抽象名词和真实界面一一对应
3. 给自己或团队做一套可复现的核对 SOP

### 3.7 看完第十一篇，你应该会

1. 判断某段旧文是不是过时
2. 知道 App、IDE、Windows 这几块最近主要进化在哪里
3. 不再继续用“桌面壳”“IDE 壳”这种旧理解

## 4. 学完以后，你就应该掌握的 4 个层次

### 4.1 第一层：能跑起来

你应该会：

1. 安装 Codex CLI
2. 看懂版本、登录状态、当前模型
3. 用安全默认配置开一个可用会话

### 4.2 第二层：能稳定使用

你应该会：

1. 用 `profiles`
2. 区分 `read-only`、`workspace-write`、`danger-full-access`
3. 用 `AGENTS.md` 固定团队规则

### 4.3 第三层：能把它真正用进开发

你应该会：

1. 在 IDE 里用 Agent 模式协作改代码
2. 在 App 里用 `Worktrees`、`Review pane`、`Built-in Git`、`Integrated terminal`
3. 在大任务上用 `Cloud delegation` / `Handoff`

### 4.4 第四层：能自己排错

你应该会：

1. 看 `/status` 和 `/debug-config`
2. 查 `model_provider`、`base_url`、`auth.json` / keyring
3. 排查 Windows-native / WSL / `CODEX_HOME` 差异
4. 知道故障该回哪篇专题，而不是乱删配置

## 5. 什么时候该看哪篇，不要乱跳

如果你现在遇到的是这些情况，直接按下面跳：

1. “我完全不懂 Codex 配置层次”：
   去第三篇
2. “我不懂命令名和字段名”：
   去第八篇
3. “我知道概念，但不会填配置”：
   去第五篇
4. “我想知道现在最常用的功能到底怎么用”：
   去第十二篇
5. “我想确认这些能力在界面上到底在哪”：
   去第七篇
6. “我怀疑自己现在看的还是旧认知”：
   去第十一篇
7. “Codex 在 Windows / Node / PowerShell 上出怪问题了”：
   去第十篇和中转切换排障专题

## 6. 哪些内容不是给小白一开始就深挖的

下面这些内容不是“不重要”，而是不要在第一个小时就陷进去：

1. 第四篇第三方多线路对比
2. 第一篇 rpcod 单线路实操
3. 第九篇 `.codex` 本地目录深挖
4. 第十篇 PowerShell / MCP / CC Switch 故障复盘

它们更适合：

1. 你已经会基本使用后，再按需查
2. 你真遇到对应线路或对应故障时再看

## 7. 一句话学习地图

如果要把整套资料压缩成一句话，就是：

1. 第三篇让你“懂原理”
2. 第八篇让你“懂名词”
3. 第五篇让你“会填配置”
4. 第六篇让你“懂三端关系”
5. 第十二篇让你“会用当前常用功能”
6. 第七篇让你“能对照界面操作”
7. 第十一篇让你“知道哪里升级了、旧说法该怎么删”

## 8. 小白读完后的最低达标标准

如果主人希望这套文档真的做到“小白读完也能掌握 Codex”，那最低标准应该是：

1. 能自己跑通一套安全默认配置
2. 能分清 CLI / IDE / App 分别适合什么
3. 能说清 `Worktrees`、`Cloud delegation`、`Review pane`、`AGENTS.md`、`MCP` 分别是什么
4. 能知道哪些旧说法已经不该继续当主线
5. 出问题时知道先去哪个专题排，而不是乱改配置

如果这 5 条做到了，这套文档就不是“堆资料”，而是真的能教会人。
