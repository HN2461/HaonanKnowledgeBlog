# Agent Skills 目录

> 2026-05-22 复核说明：这一组文章已按当前能核对到的官方资料和本地 Codex 实装情况重新收口。现在不再把所有工具都写成“完全同一套机制”，而是优先区分三层：
>
> 1. `SKILL.md` 这一类可移植的“技能包”思路
> 2. Kiro / Codex 当前可确认支持的技能目录方案
> 3. Cursor / Claude Code 当前官方文档里更明确的 `Rules`、`AGENTS.md`、自定义命令方案

## 适合先读哪篇

如果主人想先搞清楚“这到底是不是同一套东西”，先看第一篇。

如果主人已经会写 `SKILL.md`，想分清哪些写法还稳、哪些说法已经容易过时，直接看第二篇。

如果主人想拿现成模板开干，看第三篇。

如果主人想做团队共享、统一分发、找靠谱来源，看第四篇。

## 本组文章现在的写法原则

- 只把 `name`、`description` 继续当作跨工具最稳的基础字段。
- 只把 Kiro 官方 skills 文档、OpenAI `openai/skills` 仓库与本地 Codex 实装情况，当作这轮复核的硬依据。
- Cursor 当前官方文档主轴是 `Rules` 与根目录 `AGENTS.md`，因此不再把它写成“和 Kiro / Codex 一样的技能目录体系”。
- Claude Code 当前这轮核对到的官方页面，重点是自定义 slash commands，因此文中凡是更激进的“高级 skill 字段”都会降级成“版本敏感能力”，不再当成通用规范。

## 建议搭配阅读

- 想给 Codex 本地装技能：先看第四篇，再对照 `~/.codex/skills/` 实际目录。
- 想给项目沉淀长期规范：不要急着写 skill，先判断是不是更适合写 `AGENTS.md`、`CLAUDE.md` 或 `.cursor/rules`。
- 想跨工具复用：先按第一篇的“最小可移植层”写，再看第三篇如何分叉成工具专属版本。
