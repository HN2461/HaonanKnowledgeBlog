# 第 7 篇：Vue + Express + MongoDB 完整上线检查清单

资料核对时间：2026-06-08。

这一篇是实战清单。

你可以把它当成部署时的操作单，从上往下走。

## 1. 本文假设的项目结构

假设你有一个前后端分离项目：

```txt
my-fullstack-app/
  frontend/      Vue + Vite
  backend/       Node + Express
```

部署目标：

```txt
前端访问：https://example.com
接口访问：https://example.com/api/health
后端本机：http://127.0.0.1:3000
数据库：MongoDB
```

服务器目录：

```txt
/var/www/my-fullstack-app/dist    Vue 打包产物
/opt/my-fullstack-api             Express 后端
```

## 2. 本地前端构建

在本机：

```bash
# 进入前端项目
cd frontend

# 安装依赖
npm install

# 构建生产文件
npm run build
```

确认生成：

```txt
frontend/dist/index.html
frontend/dist/assets/
```

小白注意：

```txt
dist 是部署给 Nginx 的。
src 是开发源码，不是最终给用户访问的文件。
```

## 3. 后端准备健康检查接口

后端至少准备一个接口：

```js
import express from 'express'

const app = express()

app.use(express.json())

// 健康检查接口
// 部署时用它确认 Express、PM2、Nginx 反向代理是否通
app.get('/api/health', (req, res) => {
  res.json({
    ok: true,
    message: 'server is healthy'
  })
})

const port = Number(process.env.PORT || 3000)

// 监听本机地址，减少直接暴露应用端口的风险
app.listen(port, '127.0.0.1', () => {
  console.log(`api listening on http://127.0.0.1:${port}`)
})
```

## 4. 服务器目录准备

登录服务器：

```bash
ssh root@你的服务器IP
```

创建目录：

```bash
# 前端静态资源目录
sudo mkdir -p /var/www/my-fullstack-app/dist

# 后端应用目录
sudo mkdir -p /opt/my-fullstack-api
```

如果你用普通用户部署，还要注意目录权限。小白阶段可以先理解：

```txt
谁运行 Nginx，就要能读取前端静态文件。
谁运行 Node，就要能读取后端代码和 .env。
```

## 5. 上传前端 dist

方式一：本机上传：

```bash
# 在本机 frontend 目录执行
# 把 dist 里的内容上传到服务器目录
scp -r ./dist/* root@你的服务器IP:/var/www/my-fullstack-app/dist/
```

方式二：服务器拉代码后构建：

```bash
# 在服务器上进入项目
cd /opt/my-project/frontend

# 安装依赖
npm install

# 构建
npm run build

# 同步 dist 到 Nginx 静态目录
sudo cp -r dist/* /var/www/my-fullstack-app/dist/
```

小白建议：

```txt
第一次练习可以上传 dist。
熟练后建议服务器拉代码或 CI/CD 自动构建。
```

## 6. 部署后端代码

服务器上：

```bash
# 进入 /opt
cd /opt

# 拉后端项目，地址换成自己的
git clone https://github.com/your-name/my-fullstack-api.git my-fullstack-api

# 进入后端目录
cd my-fullstack-api

# 安装生产依赖
npm install --omit=dev
```

创建 `.env`：

```bash
nano .env
```

内容示例：

```bash
# 生产环境
NODE_ENV=production

# Express 端口
PORT=3000

# MongoDB 连接字符串，密码换成真实强密码
MONGODB_URI=mongodb://app_user:strong_password@127.0.0.1:27017/my_app?authSource=my_app
```

## 7. 启动后端

先直接测试：

```bash
# 直接启动一次，确认没有语法错误和环境变量问题
NODE_ENV=production node app.js
```

另开一个终端测试：

```bash
# 本机访问后端健康检查
curl http://127.0.0.1:3000/api/health
```

没问题后，用 PM2：

```bash
# 安装 PM2
npm install -g pm2

# 启动后端
pm2 start app.js --name my-fullstack-api

# 查看状态
pm2 list

# 保存进程列表
pm2 save

# 配置开机自启，按命令输出提示继续执行
pm2 startup
```

## 8. 配置 Nginx

创建配置文件：

```bash
# 文件名可以按你的域名或项目名命名
sudo nano /etc/nginx/sites-available/my-fullstack-app
```

写入：

```nginx
server {
  # HTTP 端口
  listen 80;

  # 换成你的域名；没有域名时可以临时写服务器 IP
  server_name example.com;

  # Vue dist 目录
  root /var/www/my-fullstack-app/dist;
  index index.html;

  location / {
    # 支持 Vue Router history 模式刷新不 404
    try_files $uri $uri/ /index.html;
  }

  location /api/ {
    # 把 API 请求转发给 PM2 管理的 Express
    proxy_pass http://127.0.0.1:3000;

    # 传递真实请求信息
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
  }
}
```

启用配置：

```bash
# 建立软链接到 sites-enabled
sudo ln -s /etc/nginx/sites-available/my-fullstack-app /etc/nginx/sites-enabled/my-fullstack-app

# 检查配置
sudo nginx -t

# 重载 Nginx
sudo systemctl reload nginx
```

注意：

```txt
不同 Linux 发行版的 Nginx 目录结构可能不同。
Ubuntu / Debian 常见 sites-available / sites-enabled。
有些系统直接使用 /etc/nginx/conf.d/*.conf。
```

## 9. 配置防火墙

Ubuntu ufw 示例：

```bash
# 先允许 SSH，避免把自己锁在外面
sudo ufw allow 22

# 允许 HTTP
sudo ufw allow 80

# 允许 HTTPS
sudo ufw allow 443

# 查看状态
sudo ufw status
```

如果云服务器还有安全组，也要在云控制台放行：

```txt
22：SSH
80：HTTP
443：HTTPS
```

不要随手开放：

```txt
3000：Express 应用端口
27017：MongoDB 数据库端口
```

除非你非常清楚自己在做什么，并且已经限制访问来源。

## 10. 配置 HTTPS

方式一：Certbot。

按照 Certbot 官方网站选择：

```txt
软件：Nginx
系统：你的服务器系统
```

然后按它给出的命令申请证书。

方式二：宝塔。

在宝塔网站管理里：

```txt
站点 -> SSL -> 申请证书 -> 开启 HTTPS
```

无论哪种方式，前提通常是：

- 域名已解析到服务器。
- 80 端口可访问。
- Nginx 站点配置能正常响应。

## 11. MongoDB 检查

上线前确认：

```txt
MongoDB 已开启认证。
应用使用专用数据库用户。
用户只有 readWrite 当前库权限。
MONGODB_URI 放在 .env。
27017 没有暴露给所有公网。
已经准备备份方案。
```

本机测试：

```bash
# 在服务器上测试后端接口
curl http://127.0.0.1:3000/api/health
```

如果接口里依赖数据库，还要测试一个真实读写接口。

服务器本机：

```bash
# Nginx 配置正确
sudo nginx -t

# Nginx 正在运行
```

```txt
https://example.com

```

## 13. 常见错误对照表

| 现象 | 可能原因 | 先查什么 |
|---|---|---|
| 域名打不开 | DNS 未生效、安全组没开、Nginx 没启动 | DNS、云安全组、`systemctl status nginx` |
| 首页 403 | Nginx 没权限读文件、目录没有 index.html | `root` 路径、文件权限 |
| 首页 404 | `root` 指错、dist 上传错层级 | 网站根目录是否直接有 `index.html` |
| 刷新子路由 404 | Vue history 模式缺少回退 | `try_files $uri $uri/ /index.html` |
| API 502 | Express 没启动或端口不对 | `pm2 list`、`curl 127.0.0.1:3000` |
| API 404 | `/api` 路径转发和后端路由不一致 | Nginx `proxy_pass`、Express 路由 |
| 数据库连接失败 | URI 错、用户权限错、MongoDB 未启动 | `.env`、MongoDB 日志 |
| HTTPS 申请失败 | 域名没解析、80 端口不通 | DNS、安全组、Nginx |

## 14. 更新项目时怎么做

前端更新：

```bash
# 本地或服务器重新构建
npm run build

# 覆盖服务器 dist
sudo cp -r dist/* /var/www/my-fullstack-app/dist/

# Nginx 静态文件更新通常不需要重启 Node
```

后端更新：

```bash
# 进入后端目录
cd /opt/my-fullstack-api

# 拉最新代码
git pull

# 如依赖变化，重新安装
npm install --omit=dev

# 重启后端
pm2 restart my-fullstack-api

# 查看日志确认没有报错
pm2 logs my-fullstack-api
```

Nginx 配置更新：

```bash
# 先检查
sudo nginx -t

# 再重载
sudo systemctl reload nginx
```

## 15. 一句话总流程

```txt
买服务器 -> SSH 登录 -> 准备目录 -> Vue 打包上传 dist -> Express 放到 /opt -> .env 配好数据库 -> PM2 启动后端 -> Nginx 配静态站点和 /api 代理 -> 放行 80/443 -> 域名解析 -> HTTPS -> 全链路检查。
```
