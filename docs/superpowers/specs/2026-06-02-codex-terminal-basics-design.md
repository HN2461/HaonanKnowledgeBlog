# Cloud Codex 终端零基础入门文章设计稿

## 1. 目标

为当前博客仓库新增一篇面向终端零基础用户的中文文章，帮助读者在使用 Cloud Codex 时掌握最常见、最实用、最不容易出错的 PowerShell 基本操作。

这篇文章的目标不是系统讲解命令行原理，也不是扩展成 Git、Node.js、PowerShell 高阶教程，而是让读者能在真实开发场景里先顺手完成最小必要操作。

## 2. 受众与边界

### 受众

- 平时会打开 Cloud Codex 终端，但对终端不熟
- 目前最熟悉 `cd 路径`，其他操作比较陌生
- 希望先掌握“够用”的基本命令，而不是一次学太深

### 不展开的内容

- 不做 Git 命令专题
- 不讲 PowerShell 脚本编程
- 不展开环境变量、权限模型、重定向、管道等进阶主题
- 不推荐高风险删除类命令作为新手常规操作

## 3. 落点与文件规划

文章放入 Codex 专题目录，作为“终端基础补齐”型内容，路径建议为：

`public/notes/AI工具/02_终端Agent流/Codex/`

文章需要包含合法 frontmatter，字段至少包括：

- `title`
- `date`
- `category`
- `tags`
- `description`

如果需要让目录页更顺滑，可在 Codex 目录页补充一条入口链接。

## 4. 内容结构

采用“场景带命令型”写法，而不是纯命令罗列。

建议结构如下：

1. 先解释“终端里最重要的不是背命令，而是知道自己在哪、当前能看什么、下一步想做什么”
2. 讲最常用的基础场景
3. 每个场景只放 2 到 4 个命令，并解释“什么时候用”
4. 单独补一节“在 Cloud Codex 里最常用的一套最小操作流”
5. 结尾给一份“新手先记这几个命令就够用”的速查清单

## 5. 计划覆盖的核心场景

### 场景一：知道自己当前在哪

- `pwd`
- `Get-Location`

### 场景二：进入目标目录

- `cd 路径`
- `cd ..`
- `cd /d` 不写入正文，因为它偏向 cmd 语境，避免混淆

### 场景三：查看当前目录里有什么

- `dir`
- `ls`

### 场景四：切换到上一级、下一级和常见路径

- 相对路径
- 绝对路径
- 带空格路径的写法

### 场景五：查看文件内容

- `type`
- `Get-Content`

### 场景六：新建基础文件夹或文件

- `mkdir`
- `New-Item`

### 场景七：复制、移动、重命名

- `copy`
- `move`
- `ren`

### 场景八：清屏、终止、重跑

- `cls`
- `Ctrl + C`
- 方向键调用历史命令

### 场景九：在项目里跑最常见命令

- `npm install`
- `npm run dev`
- `git status`

这里只讲“怎么看懂这些命令在做什么”，不展开具体工具链教程。

## 6. 风格要求

- 全文保持小白友好
- 尽量使用中文解释，不假设读者熟悉术语
- 每个命令都要附一句“它是干什么的”
- 不堆过多等价命令，避免初学者选择困难
- 尽量结合 Cloud Codex 使用场景，而不是脱离实际单讲 PowerShell

## 7. 风险与处理

### 风险一：文章写成命令百科

处理方式：严格限制在“第一次最该学会的操作”范围内。

### 风险二：文章和现有 Git 速查内容重叠

处理方式：只保留 `git status` 作为“开发时常见命令”的轻触达，不展开 Git 工作流。

### 风险三：PowerShell 与 cmd 写法混杂

处理方式：正文优先使用 PowerShell 常见写法，必要时补一句“别名也能用”，但不展开多壳差异。

## 8. 验收标准

如果读者读完后能做到下面这些事，就说明文章达标：

1. 知道如何确认自己当前目录
2. 知道如何进入项目目录和返回上一级
3. 知道如何查看当前目录下的文件和文件夹
4. 知道如何中断一个卡住的命令
5. 知道如何在项目目录里执行最基本的开发命令
6. 不会因为文章引导而直接去使用高风险删除命令
